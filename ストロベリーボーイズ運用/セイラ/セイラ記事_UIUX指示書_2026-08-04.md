
## 1. 【必須】記事末尾の内部リンク3本を追加する

### 何が問題か

制作の鉄則6「記事末尾は内部リンクで締める（出勤スケジュール／料金／初めての方へ等、読者の次の行動につながる3本）」に対し、現状のCTAは**キャスト個別ページへの1本だけ**です。しかもハードコードで、記事ごとに変えられません。

DBには `interview_meta.cta_data` というフィールドが最初から用意されているのに、**どこからも読まれていません。**

### どうするか

`cta_data` を読んでリンクカードを描画する。実装コードは実装パッケージ「5. 作業2の参考実装」にあります。

### デザイン指定

| 項目 | 指定 |
|---|---|
| 配置 | 既存の予約CTAボックスの**すぐ下**、関連記事セクションの上 |
| 見出し | h2「次はこちらもどうぞ」（`cta_data.heading` から） |
| レイアウト | デスクトップ3カラム／モバイル1カラム縦積み |
| カード | 白背景・角丸12px・薄いピンクの枠線（`#F0DCE1`）・影は控えめ |
| 文字 | ラベル14px太字ピンク（`#E8567A`）／説明12pxグレー（`#777`） |
| ホバー | 1〜2px浮かせる（既存の関連記事カードと同じ挙動に揃える） |
| マークアップ | `<nav aria-label="関連ページ">` + `<ul><li>` |

**優先順位の理由**: 予約ボタン（＝コンバージョン直行）を一番上に残したまま、その下に「まだ決めきれない人」の受け皿を3本置く形です。読者の意思決定段階が違うので、順序を逆にしないでください。

## 2. 【必須】インタビュアーのアイコンが出ないバグ

`resolveIconUrl` は `speakerType === 'interviewer'` でスタッフ写真を引きに行きますが、カズヤ記事は `speaker: 'staff'` で投入されています。結果、イトウさんのアイコンが解決できず、**キャスト写真のフォールバックが出ています**（＝対話の左右でセイラさんの写真が両方に出る、という見え方になる可能性）。

判定を `'interviewer' || 'staff'` の両対応に広げてください。セイラ記事は `'interviewer'` で投入するので新規側は問題ありません。

あわせて、`photos.staff_photos['イトウ']` に有効な画像パスが入っているか確認してください。ここが空だと同じ症状になります。

## 3. 【推奨】シリーズバッジを出す

現状 `series_slug` が入っている記事だけバッジ（「キャストインタビュー vol.4」「fukuokaエリア」）が出ます。カズヤ記事は `series_slug` 未設定なのでバッジが出ていません。

セイラ記事は `series_slug: 'cast-interview'` を入れているので出ます。**既存3本にも同じ値を入れてください**（1行のUPDATEで済みます）。シリーズ感が出ると回遊率が変わります。

もうひとつ、エリアバッジの表示が `{interviewMeta.area}エリア` なので、**`fukuoka` だと「fukuokaエリア」と英語で出ます**。ここは日本語に変換してください。

```tsx
const AREA_LABEL = { fukuoka: '福岡', yokohama: '横浜', tokyo: '東京', osaka: '大阪', nagoya: '名古屋' };
// ...
{AREA_LABEL[interviewMeta.area] ?? interviewMeta.area}エリア
```

## 4. 【推奨】写真4枚の配置意図

写真は「読み疲れる直前」に置いています。スクロールのリズム設計です。

| 位置 | 写真 | 意図 |
|---|---|---|
| サムネイル | portrait | 一覧・SNSシェア時の顔。**明るい場所での撮影が必須** |
| 第2セクション末尾 | portrait | 「27歳に見える肌」の話の直後。文章の主張を画像が裏づける |
| 第3セクション中盤 | fullbody | 私服の話の直後。ここで一度息継ぎさせる |
| 第3セクション末尾 | ramen | ラーメン談義の直後。読者が一番「かわいい」と思う瞬間 |
| 第6セクション | handwritten | 最後のメッセージの直前。**ここが記事で一番効く1枚** |

**手書きメッセージを最後のメッセージの「直前」に置くのが肝です。** 手書き → 本人の言葉、の順で読ませると、テキストが本人の声に聞こえます。逆順にすると効果が半減します。

### 撮影の追加リクエスト（もり → セイラさん）

- portrait は**明るい室内か屋外**で。取材時の映像は暗く、本人の肌の良さ（記事の主張の柱）が伝わりませんでした
- handwritten は、カードを**手で持って**撮る形。顔は不要。手元にピントを合わせる
- ramen は丼を真上か斜め45度から。店名が写り込むなら店名確認と併せてOKをもらう

## 5. 【推奨】モバイル可読性

想定読者の大半はスマホです。以下は既存UIで確認してください。

- 本文コンテナは `maxWidth: 720` 固定。モバイルでは `padding: 0 20px` が効くので問題なし
- 吹き出しの1行あたり文字数が長すぎないか（日本語で25〜30字が上限の目安）
- FAQ の回答が長め（150〜200字）です。アコーディオンになっていない場合、開いた状態で縦に伸びるので、質問文だけ先に3つ見えるUIが望ましい
- 手書き画像は横長です。モバイルで文字が読めるサイズか実機確認してください

---

## 6. 【推奨】プロフィールカードの項目数

今回 `profile_data.fields` を9項目にしました。カズヤ記事は6項目です。9はやや多く、モバイルで縦に伸びます。**表示が窮屈なら「経験スポーツ」と「好きな食べ物」を削って7項目**にしてください（本文で両方触れているので情報は失われません）。

## 7. やらないこと

- URL・ディレクトリ構造の変更（過去にAPIが壊れた前例あり）
- 年齢確認モーダルの削除・変更
- `sr-only` 要素の削除
- 既存記事のレイアウト変更（今回の追加はすべて後方互換で、`cta_data` の無い記事では何も描画されない設計です）
- 遅延マウントでの本文描画（鉄則9: SSRのHTMLに本文が含まれること）
