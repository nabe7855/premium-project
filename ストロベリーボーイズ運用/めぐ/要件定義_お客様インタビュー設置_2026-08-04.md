# 要件定義書｜お客様インタビュー記事のサイト内設置

**対象記事**: 「このままおばあさんになりたくなかった」／あやさん（30代・既婚）
**作成日**: 2026-08-04
**作成**: SEOアナリスト / ウェブライター / UI-UXデザイナー 兼務レビュー
**前提**: 本書は計画書であり、コード変更は含まない。実装は開発AI（Gemini / Claude Code）側で行う。
**最重要制約**: **既存の機能・要素・URL・表示を一切変えないこと**。本件はすべて「追加」で成立させる。既存ファイルへの変更は本書 §7 に列挙した最小限のみとし、それ以外の改変は禁止する。

## 0. 結論サマリー（先に読む3行）

1. 設置場所は **`/store/[店舗]/voice/[記事slug]`（新設・店舗配下）**。福岡が上位表示している `/store/fukuoka/` のトピック塊に子ページとして加えることで、「女性用風俗 福岡」の地域評価をそのまま記事に流し、逆に記事の獲得トラフィックを店舗トップへ返す。
2. 既存の**セラピストインタビュー（`/store/[店舗]/interview/...`）とは別系統**にする。同じ枠に混ぜると既存の一覧・トップ・sitemap・schema の中身が変わってしまい、「既存を壊さない」制約に抵触する。
3. UI は既存 `InterviewArticleUI.tsx` を**触らずに**、体験談用の新コンポーネントを別途用意する。CTA の終着点はセラピスト個別ページではなく **「初めての方へ」→「料金」→「予約」** に変える（新規顧客獲得のため）。

## 1. ゴールからの逆算（なぜこの設置場所なのか）

### 1-1. 最終ゴール

> 地域ごとに「女性用風俗 ○○（地域名）」で1位を取り、新規顧客を獲得する。

### 1-2. 現在地（memory / GSC より）

- 「女風 福岡」= 5位圏（1ページ目定着）。「女性用風俗 福岡」= まだ1ページ目不在。
- 上位表示の主戦力は `/`（トップ）と `/store/fukuoka`。SSR化＋FV直下SEOブロックがスニペット採用された実証あり。
- 残っている差分は **鮮度の持続・被リンク・口コミ量（＝一次情報の厚み）** のみ。オンページは競合と同等以上。

### 1-3. 逆算の論理

「女性用風俗 福岡」単体KWは、**サイト全体のトピック権威**で決まる。すなわち、
「福岡 × 女性用風俗」に関する**周辺クエリを何面取れているか**が、単体KWの押し上げ要因になる。

体験談記事が取れる周辺クエリ（＝本件の獲得目標）は以下のロングテール群である。

| 優先 | ターゲットKW | 検索意図 | この記事が答えられるか |
|---|---|---|---|
| ◎ | 女性用風俗 福岡 体験談 / 女風 福岡 体験談 | 実際どうだったのか知りたい | ◎ 一次情報そのもの |
| ◎ | 女性用風俗 初めて 不安 / 怖い | 何をされるか分からない恐怖 | ◎ CHAPTER02・04が直答 |
| ○ | 女性用風俗 既婚 / 主婦 / 人妻 利用 | 自分が利用していい属性か | ◎ 主人公属性が完全一致 |
| ○ | 女性用風俗 バレない / バレたくない | 家族への露見リスク | △ 現状は言及が薄い（§6-3で加筆要件） |
| ○ | 女性用風俗 料金 高い / 初めて 安く | 費用の後ろめたさ | △ 同上 |
| △ | 女性用風俗 感想 / 使ってみた / リアル | 純粋な好奇心 | ◎ |

**この記事が単独で「女性用風俗 福岡」1位を取ることはない。** 役割は、
(a) ロングテールで新規セッションを取る入口、
(b) 「福岡×女性用風俗」トピック塊の厚みを増やして店舗トップの評価を押し上げる燃料、
(c) 迷っている読者を `/first-time` → `/price` → 予約へ運ぶコンバージョン装置、
の3つ。この3役を同時に満たす置き場所は**店舗ディレクトリ配下しかない**。

### 1-4. 却下した案と理由

| 案 | 却下理由 |
|---|---|
| `/magazine/interview/[slug]` に置く | 店舗（地域）と切り離れた階層で、地域クラスタに寄与しない。かつ後述のとおり当該URL群は既に重複の温床になっている（§9-4）。 |
| 既存 `/store/[店舗]/interview/[cast]/[article]` に相乗り | URLに `[cast]` セグメントが必須で、お客様記事にはキャストが存在しない。sitemap は castSlug が無い場合 `unknown` を出力する実装のため `/store/fukuoka/interview/unknown/aya` という不正URLが生成される。さらに既存の「セラピストインタビュー一覧」「トップのINTERVIEWセクション」「関連記事2件」にお客様記事が混入し、**既存表示が変わってしまう**。 |
| 既存 `/store/[店舗]/reviews` 内に統合 | 当該ページは既に `title = お客様の声・口コミ` を保有。長文記事を差し込むとページ主題がぼやけ、既存の口コミ一覧UIも改変が必要になる（＝既存を壊す）。 |
| 独立ドメイン / サブドメイン | 評価が分散する。系列店を外部化した方針とは目的が逆。 |

## 2. 設置場所（URL設計）

### 2-1. 新設URL

| 種別 | URL | 備考 |
|---|---|---|
| 記事詳細 | `https://www.sutoroberrys.jp/store/fukuoka/voice/aya-taikendan` | 本記事 |
| ハブ（一覧） | `https://www.sutoroberrys.jp/store/fukuoka/voice` | **公開記事が1本以上ある店舗のみ生成**。0本なら `notFound()`（既存 interview ハブと同じ流儀＝実体なきURLをsitemapに載せない方針の遵守） |
| 横浜横展開 | `https://www.sutoroberrys.jp/store/yokohama/voice/...` | 記事ができ次第、同じ仕組みで自動生成 |

- **既存URLは1本も変更しない**（URL変更禁止の方針を厳守）。本件はすべて新規パスの追加のみ。
- ディレクトリ名 `voice` はコード上の識別子。**画面表示上の名称は「体験ストーリー／利用者インタビュー」で統一**する（理由は §2-2）。
- slug は半角英数字とハイフンのみ。日本語・全角・`copy-copy` 等の自動採番は公開前に必ず整える（既存ニュースでの反省点）。

### 2-2. 命名のカニバリ回避（重要）

`/store/[店舗]/reviews` が既に **「お客様の声・口コミ」** という title を持っている。
新設ページで同じ語を使うと、同一サイト内で「お客様の声」「口コミ」の評価が2URLに割れる。

| ページ | 担当ワード | 使ってよい語 | 使ってはいけない語 |
|---|---|---|---|
| 既存 `/reviews` | 口コミ・お客様の声 | 口コミ、お客様の声、評判 | — |
| 新設 `/voice` | 体験談・体験ストーリー | 体験談、体験ストーリー、利用者インタビュー、リアルな声 | **「口コミ」「お客様の声」をtitle/H1に入れない** |

## 3. 情報設計（サイト内の位置づけと内部リンク網）

### 3-1. 記事の位置づけ

```
/store/fukuoka（店舗トップ＝地域KWの本丸）
 ├─ /first-time（初めての方へ＝不安解消・コンバージョン直前）
 ├─ /price（料金）
 ├─ /reviews（口コミ一覧＝短文・多数）
 ├─ /interview（セラピストインタビュー＝既存・触らない）
 └─ /voice（体験ストーリー＝新設・長文・少数）★ここ
      └─ /voice/aya-taikendan
```

口コミ（短文×多数）と体験談（長文×少数）は**別レイヤーの一次情報**として併存させる。前者は量で信頼を作り、後者は深さで「自分ごと化」を作る。

### 3-2. 内部リンク要件（双方向で組む）

**記事 → 出口（記事内に必ず設置）**

| 位置 | リンク先 | アンカーテキスト例 | 目的 |
|---|---|---|---|
| CHAPTER02 直後（迷いの山場） | `/store/fukuoka/first-time` | 「福岡で初めて女性用風俗を利用する方へ｜当日の流れと不安への答え」 | 離脱直前の受け皿 |
| CHAPTER03 内（料金の話の直後） | `/store/fukuoka/price` | 「料金・コース一覧を見る」 | 費用不安の解消 |
| CHAPTER04 内 | `/store/fukuoka/cast-list` | 「在籍セラピストを見る」 | 人で選びたい層 |
| 記事末CTA（第一CTA） | `/store/fukuoka/first-time` | 「初めての方へ（安心ガイド）」 | 情報CTA |
| 記事末CTA（第二CTA） | `/store/fukuoka#reservation` または予約導線 | 「ご予約・お問い合わせ」 | 行動CTA |
| 回遊ブロック | `/store/fukuoka/reviews` / `/store/fukuoka/voice` | 「ほかの利用者の口コミを見る」「ほかの体験ストーリー」 | 滞在・回遊 |

- **既存記事内のダミーリンク（`href="#"`・`example.com`）は公開前に全数差し替え必須**（過去記事で放置された前例あり）。
- アンカーテキストには「女性用風俗」「福岡」を機械的に詰め込まない。1記事あたり地域KW入りアンカーは**最大2本**まで。

**出口 → 記事（既存ページ側からの導線／すべて「追加」のみ）**

| 設置元 | 追加する要素 | 既存への影響 |
|---|---|---|
| 店舗トップ `/store/fukuoka` | 体験ストーリーセクションを1つ追加（記事0本なら `null` を返して完全非表示） | 既存セクションは順序・内容とも変更しない。挿入位置は `ReviewSection` の直後を推奨 |
| `/store/fukuoka/first-time` | ページ下部に「実際に利用した方の体験ストーリー」カード1枚 | 既存本文・見出しは変更しない |
| `/store/fukuoka/reviews` | 一覧の下に「もっと詳しい体験談を読む」導線1本 | 口コミ一覧のロジックには触れない |
| `/store/fukuoka/voice`（新設ハブ） | 記事カード一覧 | 新規のため影響なし |

## 4. データモデル要件（DBスキーマは変更しない）

既存の `media_articles` + `interview_meta` をそのまま流用する。**マイグレーション不要**。

| 項目 | 値 | 備考 |
|---|---|---|
| `media_articles.category` | `interview` | 既存の取得ロジックが `category='interview'` で絞っているため踏襲 |
| `media_articles.target_audience` | `user` | 採用側と混ざらないように |
| `media_articles.status` | `draft` → 確認後 `published` | 本人確認完了までは必ず `draft` |
| `interview_meta.article_type` | **`customer_voice`（新値）** | 当該カラムは `String`（enum ではない）ため**スキーマ変更不要**。既存値 `solo_interview` / `roundtable` / `feature` は一切変えない |
| `interview_meta.area` | `fukuoka` | 既存の表記ゆれ吸収（`fukuoka`/`福岡`）に乗る |
| `interview_meta.series_slug` | `customer-voice` | シリーズ化の識別子 |
| `interview_meta.vol_number` | `1` | あやさん回＝vol.1 |
| `interview_meta.cast_links` | **空配列** | キャストは紐付けない（紐付けると既存のキャスト関連表示に混入する） |
| `interview_meta.dialogue_data` | 章構成（§5-4） | `type: narration / photo / editor_note` を使用 |
| `interview_meta.faq_data` | FAQ 5問（§5-3） | FAQPage schema の元データ |
| `interview_meta.profile_data` | 利用者プロフィール | ただし表示見出しは「出演キャスト」ではなく「語り手プロフィール」（§5-4） |

### 4-1. 既存を壊さないための必須ガード（★最重要）

`getInterviewArticles()` は現在 `article_type` を指定しない場合**全件を返す**。ここに `customer_voice` を追加すると、以下の既存画面に**お客様記事が勝手に混入する**。

影響を受ける既存箇所（実コードで確認済み）:

- `/store/[slug]/interview`（セラピストインタビュー一覧）
- `/store/[slug]/page.tsx` → トップの `TopInterviewSection`（「セラピストインタビュー」枠）
- `/magazine/interview`（一覧）
- `/recruit`（採用トップ、`getInterviewArticles({limit:3})`）
- `InterviewArticleUI` 内の「他のセラピストインタビュー」関連記事2件
- `sitemap.ts`（`/store/{area}/interview/{castSlug}/{slug}` を生成 → castSlug が無いため `unknown` が入る）

**要件**: `getInterviewArticles()` に、`article_type` 未指定時は `customer_voice` を**除外する**既定ガードを入れる。
（例：`metaWhere.article_type = { notIn: ['customer_voice'] }` を既定とし、明示指定時のみ上書き）
既存記事はすべて `solo_interview` のため、**この変更で既存の表示・件数・並び順は1件も変化しない**。これは挙動を保存するための変更であり、挙動を変える変更ではない。

体験談側の取得は `getCustomerVoiceArticles()` を**新規追加**し、`article_type: 'customer_voice'` で明示的に絞る。

## 6. UI/UX要件

### 6-1. コンポーネント方針（既存を壊さないための最重要判断）

既存 `src/components/interview/InterviewArticleUI.tsx` は**変更しない**。理由は3つ。

1. バッジが「キャストインタビュー」固定、プロフィール見出しが「出演キャスト」固定。
2. 末尾CTAが「◯◯に会いに行く → キャスト個別ページ」固定。体験談のゴール（初めての方へ／料金）と食い違う。
3. 関連記事が `getInterviewArticles(area)` を無条件で呼ぶため、お客様記事が混ざる。

→ **`VoiceArticleUI`（新規）** を用意する。既存UIからの派生でよいが、ファイルは分ける。既存のセラピスト記事の見た目・挙動は1pxも変わらない。

### 6-2. 画面構造（上から順に）

```
[パンくず] トップ / 福岡店 / 体験ストーリー / 記事タイトル
[ラベル] 体験ストーリー vol.1 ／ 福岡
[H1]
[語り手情報＋読了目安（約7分）＋公開日]
[ヒーロー画像（顔なし・本人写真）] ← LCP対象。ここだけ priority
[リード（4段落）]
[目次] ← 新規要件。章タイトル5本＋FAQへのアンカー

  └ CH02直後：インライン導線カード「初めての方へ」
  └ CH03内：インライン導線「料金・コース」

[店舗共通フッター]
```

- ヘッダー／フッターは**既存の店舗テンプレート（FukuokaHeader / FukuokaFooter）をそのまま利用**する。専用ヘッダーを作らない。ユーザーが記事から店舗回遊に戻れることがコンバージョンの前提。
- **モバイルの固定CTA（`MobileStickyButton`）が既に存在する店舗ページ構成のため、記事内にさらに追従CTAを足さないこと**。二重固定はUXを壊し、CLS/操作性の両面で悪化する。記事内CTAは静的ブロックのみ。

### 6-3. 読者心理の設計（新規顧客獲得の観点）

読者は「怖い → 分かった → できそう → やってみる」の順にしか動かない。CTAの中身をこの段階に合わせる。

| 段階 | 記事上の位置 | 提供するもの | CTA文言（例） |
|---|---|---|---|
| 怖い | CH02（迷いの山場） | 「あなただけじゃない」 | 情報CTA：`同じ不安への答えをまとめました（初めての方へ）` |
| 分かった | CH04（当日の流れ） | 具体の透明性 | 情報CTA：`料金・コースを見る` |
| できそう | 記事末① | 心理的ハードル低減 | `私も一歩踏み出してみようかな、と思ったら` → 初めての方へ |
| やってみる | 記事末② | 行動 | `ご予約・お問い合わせ` |

- **CTAで煽らない・断定しない**（誇大表現禁止の方針）。「必ず」「絶対」「日本最大級」等は使用禁止。
- 「安心と安全を買っている」というご本人の言葉が本記事最大の資産。プルクオートとして視覚的に強調する（`VoiceArticleUI` に `pullquote` 表示を持たせる）。

### 6-4. 記事本文への加筆要件（ウェブライター観点）

現行原稿は情緒面が強く、**検索需要の大きい実務情報が薄い**（インタビュー時の弱点＝実務フリクション30点の指摘と一致）。以下を、**取材で裏の取れた範囲で**加筆する。想像での加筆は禁止。

| 加筆項目 | 想定KW | 備考 |
|---|---|---|
| 実際に払った金額感・コースの選び方 | 「料金」「初めて 安く」 | 具体額は変動するため「新人コースを選んだ」等の事実ベースで |
| 所要時間・どうやって数時間を作ったか | 「時間」「何時間」 | 子育て中の時間捻出は同属性読者に刺さる |
| 家族に知られないための実際の工夫 | 「バレない」 | ご本人が話した範囲のみ。過度な指南はしない |
| 待ち合わせ場所（自宅／ホテル）の実際 | 「福岡」「天神」「博多」 | 地域KW回収の主戦場 |
| 予約から当日までの連絡の流れ | 「予約 方法」「流れ」 | `/first-time` への自然な橋渡し |

- **未取材箇所の想像加筆は公開前に全削除**。別紙「要確認リスト」でご本人確認が取れた記述のみ残す（現行HTML冒頭の注記に該当箇所が明記されている）。
- 免責文を必ず設置：「本記事は個人の体験に基づくもので、感じ方には個人差があります」。

## 8. パフォーマンス要件（CWV）

現状の記事セットは画像9点で**約1.6MB**。LCP改善が継続課題である以上、記事側で膨らませない。

| 項目 | 要件 |
|---|---|
| 画像合計 | **1記事あたり 900KB 以下**（現状1.6MB → 再エンコード必須） |
| 配信 | R2 経由。ローカル `images/` フォルダのアップロードではなく、既存の画像配信フローに載せる |
| 形式・寸法 | WebP 維持。表示幅720pxに対し原寸1000〜1400pxは過大 → **長辺1080px上限**に再書き出し |
| 最大の1枚 | `aya-comic-04-futon-search.webp` が362KB → 150KB以下へ |
| 読み込み | ヒーロー1枚のみ `fetchpriority=high` / `priority`。**他8枚はすべて `loading="lazy"` `decoding="async"`** |
| CLS | 全 `<img>` に `width` / `height` 指定必須（現行HTMLは指定済み。実装時も維持） |
| フォント | 記事専用のWebフォント追加読み込みは禁止（既存サイトのフォント設定に従う） |
| 計測 | デプロイ**15分後**に×3回、中央値で判定。対象は `/` と `/store/fukuoka` の2本固定＋今回は記事URLを追加 |
