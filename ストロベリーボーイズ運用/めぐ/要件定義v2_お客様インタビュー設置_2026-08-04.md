## 1. なぜ「ルート直下のコラム」が正しいのか（根拠4点）

### 根拠1：自社の戦略文書が既にそう定義している

リポジトリ内の `MEDIA_SEO_STRATEGY.md`（統合メディアSEO・コンセプト設計書）には、役割分担が明記されている。

- **イケジョラボ（`/amolab`）** … 狙うKW：`女性用風俗 体験談` / `初めての女性向風俗` / `彼氏 セックスレス` ほか。位置づけは「女性が安心して性にまつわる全般を学べるメディア」。
- **店舗ページ（福岡・横浜）** … 狙うKW：`[地域名] 女性用風俗` / `女風 [地域名]` / `[博多/天神/みなとみらい] 女性用風俗`。位置づけは「メディアで醸成された信頼を予約に変える場所」。

つまり **「体験談＝メディア側」「地域KW＝店舗側」** は既に決まっている設計であり、v1案はこの設計に逆行していた。今回のご提案は元の設計に戻す動きになる。

### 根拠2：`/amolab` には既に「体験談」カテゴリが用意されていて、中身が無い

`/amolab` のカテゴリ導線には最初から以下が並んでいる。

> 初めての方へ ／ セルフケア ／ パートナーと ／ 恋愛・相談 ／ **体験談（説明文：ユーザーのリアルな声）** ／ ラブグッズ ／ 女風ガイド

**「体験談」枠は器だけあって空**という状態。あやさんの記事は、この器のために書かれたと言っていいほど適合している。新しい箱を作る必要がない。

### 根拠3：年齢確認モーダルを通らずに読める（これが決定的）

`AgeVerificationGuard` の除外プレフィックスに `/amolab` と `/ikeo` が入っている。

```
excludedPrefixes = ['/admin', '/cast', '/age-check', '/login', '/api', '/amolab', '/ikeo']
```

一方 `/store/...` 配下はモーダル対象。
**検索から初めて来た人に、いきなり年齢確認モーダルを出すのは、新規顧客獲得における最大級の離脱要因**である。記事を `/store/` 配下に置いた v1 案は、この一点だけでも不利だった。モーダルは既存方針どおり「削除しない」まま、モーダルの手前で記事を読ませられる `/amolab` に置くのが最適解になる。

### 根拠4：1記事で5拠点に送客できる（root配置でしかできないこと）

福岡・横浜は自社ドメイン、東京・大阪・名古屋は外部系列ドメイン。
記事を店舗配下に置くと「その店舗の記事」にしかならないが、ルート直下なら記事末に**「お住まいのエリアから選ぶ」ブロック**を置いて、5拠点すべてに送客できる。かつ系列サイトからの相互リンク先としても、店舗ページより中立的なコラムのほうが張りやすい。

## 3. 地域KWをどう担保するか（root配置の唯一の弱点への対策）

正直に書く。ルート直下に置く弱点は1つだけある。**「女性用風俗 福岡 体験談」のような地域×体験談の複合KWは、店舗配下に置いたほうが取りやすい。** 全国区の「女性用風俗 体験談」はポータル・まとめサイトが強く、競争が激しい。

これを次の3層で埋める。

### 層1：店舗側セクションのテキストで地域面を取る（最重要）

店舗トップに置くセクションは、**ただのリンク集にしない**。見出しと抜粋文に地域語を含め、店舗ページ自身のコンテンツとして地域×体験談を拾わせる。

- セクション見出し（H2）：`福岡で女性用風俗を利用した方のリアルな体験談`（横浜店は「横浜で〜」）
- リード文：`天神・博多エリアでストロベリーボーイズ福岡店をご利用いただいた方の、予約前の不安から当日の流れまで。実際の声をご紹介します。`
- カードのリンクテキスト：`半年迷って予約ボタンを押すまで｜30代・既婚あやさんの体験談`

これで**店舗ページ側が「福岡 × 体験談」を保持**し、記事本体は非地域KWを取りにいく。役割が重複しない。

### 層2：記事内に「エリアから探す」ブロックを置く

記事末に、福岡・横浜（自社）＋東京・大阪・名古屋（外部系列）への導線ブロックを設置。
アンカーテキスト例：`福岡（天神・博多）の女性用風俗を見る` / `横浜（みなとみらい・関内）の女性用風俗を見る`。
これにより記事URL自体も地域語を保持しつつ、送客が全拠点に届く。

### 層3：2本目以降で地域体験談を作る

あやさん回（vol.1）は非地域の共感型。vol.2以降で「福岡在住の方」「横浜在住の方」と、**待ち合わせ場所や地域名が自然に出てくる回**を作る。そのときに初めて地域×体験談の複合KWを正面から取りにいく。1本目でそれを狙わない。

## 6. UI/UX要件

### 6-1. 新規コンポーネントは作らない

`/amolab/[slug]` は `NoteArticleUI` が `article.content` を**HTMLとしてそのまま描画**する実装（`dangerouslySetInnerHTML` + Tailwind Typography）。すでに以下が効く。

- `h2` / `h3` の見出しスタイル、`p` の余白
- `blockquote`（プルクオート・生声の引用に使える）
- `img`（角丸・上下マージン自動）
- 独自クラス `.sep` / `.personal-note` / `.step-list` も定義済み

→ **あやさんの記事HTMLは、ほぼそのまま `content` に入れられる。** UIコンポーネントの新規開発ゼロ。

### 6-2. content に入れる前のクリーンアップ（必須）

| `<style>` ブロック全体 | **削除**（NoteArticleUI 側のprose設定と競合する。記事固有CSSを持ち込まない） |
| `href="#"` / `example.com` のダミーリンク（CTA・関連記事・FAQ内） | 実URLへ全数差し替え |

| `var(--navy)` 等の未定義CSS変数 | 削除 |
| `<title>` / `<meta>` / JSON-LD | HTMLからは外し、DB側のフィールド（seo_title / seo_description）とページ側schemaで管理 |

## 7. 先に潰しておくべき既存の穴（本件の効果を左右する）

調査中に見つかった、**放置すると記事を置いても効きにくくなる**既存の問題。

### 7-1. `/amolab` 系がsitemapに1本も入っていない（最優先）

`sitemap.ts` の media 記事生成ブロックは**コメントアウトされたまま**で、生成対象は `/magazine/interview` のみ。
`/amolab`、`/amolab/[slug]`、`/amolab/jiten/*` は**すべてsitemap未掲載**。

- 対応：sitemap末尾に `/amolab` と公開済み `category='amolab'` 記事のURLを生成するブロックを**追加**する。既存ブロックは1行も変更しない。
- コメントアウトされた旧ブロックは `/magazine/[slug]` という**存在しないパス**を生成する内容なので、復活させず新規に書く。

### 7-2. `/amolab/[slug]` に canonical が無い

`generateMetadata` に `alternates.canonical` が未設定。自己参照canonicalを追加する。

### 7-3. カテゴリ導線が `?tag=` クエリのみ

`/amolab?tag=体験談` はクエリパラメータのため、単独URLとしての評価が乗りにくい。

- 短期：現状維持でよい（記事本体で戦う）。ただし `/amolab` 本体に自己参照canonicalを付け、`?tag=` 付きURLがsitemapに入らないようにする。
- 中期：`/amolab/tag/[tag]` のディレクトリ化を別系統で検討。**今回は着手しない。**

### 7-4. `/magazine` への404リンク

`/amolab` のナビに「トップページ → `/magazine`」があるが、`/magazine` には `page.tsx` が存在せず404（sitemap内のコメントにも "/magazine (404)" と明記されている）。

- 対応：リンク先を `/amolab` または `/` に修正（1行）。**別系統でよいが、本件と同時に直しても副作用は無い**。

### 7-5. インタビュー記事の3URL重複（本件と切り離す）

同一のインタビュー記事が `①/magazine/interview/[slug]`（canonical無し）`②/store/[店舗]/interview/[cast]/[article]`（canonical有）`③/store/[店舗]/cast/[cast]/interview/[article]` の最大3URLで到達可能。②を正としてcanonicalを統一する案が有力だが、**今回のリリースには含めない**（1リリース1系統の原則）。

## 付録B. v1案（`/store/[店舗]/voice/` 新設）を撤回した理由

記録として残す。

1. 年齢確認モーダルの対象配下になり、検索からの初回訪問で離脱が発生する。
2. 同一記事を福岡・横浜の両方で見せられない（URL重複か、片方が空になる）。
3. 既存 `getInterviewArticles()` が全件返す実装のため、除外ガードを入れないとセラピストインタビュー一覧・トップ枠・`/recruit`・sitemap の4箇所に混入する。改修が必要＝既存を触るリスクが増える。
4. `MEDIA_SEO_STRATEGY.md` が定義する「メディア＝非地域KW／店舗＝地域KW」の役割分担に逆行する。
5. 新規ルート2本・新規UIコンポーネント複数が必要で、実装量が大きい。

**v2 はこの5点すべてを解消する。**
